# 실행기 최적화

현재 C++ 적용 사항과 50초 목표, 제외한 시도는 [최적화 실험 정리](optimization-experiments.md)에 정리되어 있다.

이 문서의 표와 측정은 C++ 전환 전 Python 실행기를 설명한다. 현재 C++ 경로에는 Q8 복원, CPU/GPU 분할, Q/K/V packing과 Metal 융합 커널을 이식했다. 아래 속도 및 수치 결과는 C++ 경로의 보증이 아니다.

측정 조건과 데이터는 [벤치마크](benchmarks.md)를 따른다. 여기서는 당시 Python 코드가 어떤 계산을 바꿨는지 설명한다.

## 적용

| 변경 | 목적·동작 |
|---|---|
| Q8 가중치의 1회 복원 | 큰 스트림의 사용 가중치를 BF16로 복원해 메모리에서 재사용. 디스크 체크포인트는 유지 |
| CPU/GPU 출력 채널 분배 | 큰 MLP 입력 투영 약 45%를 CPU FP32, 나머지를 GPU BF16로 실행. 각 출력의 전체 내적을 한 장치가 수행 |
| Q/K/V packing | 양자화 상태에서 행을 먼저 묶고 복원. 첫 사용의 여러 작은 할당·평가 줄이기 |
| 정규화·RoPE·배치 융합 | packed QKV를 직접 읽어 Q/K 정규화·RoPE·V 배치를 처리. strided view의 숨은 복사 줄이기 |
| modulation·잔차·SwiGLU 융합 | 원본 자료형의 중간 반올림 단계 보존 |
| 작은 스트림 보존 | 1,024토큰 미만 구간은 원본 attention/FF/정규화 경로 사용 |
| 버전 고정 | 검증한 MFLUX 커밋과 MLX 0.32.4 사용 |

CPU 가중치는 복원된 BF16 값을 FP32로 표현한다. 추가 양자화로 정보를 줄이지 않는다. LayerNorm은 원본 MLX 연산을 유지하며 RMS 합산 순서, 정확한 역제곱근, RoPE의 별도 곱셈·덧셈과 SiLU의 typed arithmetic을 맞췄다.

참조 스트림은 필요한 크기에 도달할 때 준비하고 같은 모델 수명 동안 재사용한다. 설치된 MFLUX 소스는 수정하지 않는다. 당시 프로젝트 런처가 해당 프로세스의 클래스에만 패치를 활성화했다. 이전 코드는 Git 커밋 `15b8bf1`에 보관되어 있다.

## 제외한 실험

| 실험 | 관찰·선택 |
|---|---|
| FP16 행렬곱 | 유의미한 추가 속도 이점 없이 수치 차이 발생 |
| 직접 만든 Metal GEMM 15개 조합 | 가장 나은 수정 버전 약 0.119초로 native BF16 약 0.106초보다 느림 |
| Strassen 1·2단계 | 큰 MLP 입력 약 0.147·0.211초; 버퍼·합산 비용 증가 |
| 전치·행 분할 배치 | 개선이 작거나 느려 기본 경로에 추가하지 않음 |
| CPU BF16 | 반올림 차이로 CPU FP32로 대체 |
| QKV·출력 투영까지 CPU 분산 | 실제 블록 0.268~0.349초로 MLP 입력만 분산한 0.238초보다 느림 |
| 더 낮은 비트·스텝 생략 | 현재 측정의 수치 보존 목표와 맞지 않아 적용하지 않음 |
| ANE/Core ML | 당시 환경에서 검증된 BF16 동등 경로를 확보하지 못함 |

위 짧은 시간은 특정 층·입력의 microbenchmark이며 전체 생성 시간이 아니다. CPU를 더 많이 사용한다고 항상 빨라지지 않는다. 약 45% 분배는 M3 Pro의 실제 블록·전체 계산으로 선택했다.

## 보존 검증과 범위

원본과 최적화 실행 후 최종 잠재 텐서는 한 통제된 입력에서 부호 비트까지 동일했다. 작은 입력·작은 참조·큰 참조 추가·참조 반복의 합성 검사도 기록에 포함한다. 모든 프롬프트나 다른 MLX 버전의 동일함을 증명하지는 않는다.

초기 잘못된 토큰 modulation과 자체 LayerNorm, 무작위 임시 투영 초기화, 층별 불필요한 동기화, 미사용 실험 준비 함수는 최종 경로에서 제거했다. 실험용 GEMM/Strassen 코드는 배포 경로에 포함하지 않았다.

현재는 매번 새 프로세스로 실행하는 고정 크기 CLI 경로다. 가변 크기 상주 서버·모델 export·노출하지 않은 LoRA는 검증하지 않았다. 문제가 있거나 메모리 절충이 맞지 않으면 `IMAGEN_RUNTIME=0`으로 C++의 가중치 복원과 CPU/GPU 분할을 끌 수 있다.
