# 16스텝 속도 실험

2026-10-28, M3 Pro 36GB, MLX 0.32.4. 모델 로딩과 인코딩은 제외하며 첫 그래프 준비와 Q8 가중치 복원은 포함한다. 최종 잠재값은 동일 입력의 기존 Python 최적화 경로와 비교한다. 각 기록은 1회이며 온도·부하 등의 영향을 받는다.

동일한 편집 입력(출력 704·참조 1320·텍스트 240 토큰):

| 실험 | 스텝 | 계산 시간 | 결과 |
|---|---:|---:|---|
| 기존 C++ | 16 | 75.38초 | 기준 |
| C++ 전체 그래프 `mx::compile` | 16 | 71.87초 | Python과 잠재값 비트 일치 |
| C++ 잔차 입력 순서 변경 | 16 | 72.91초 | Python과 잠재값 비트 일치 |
| 기존 C++ | 8 | 37.90초 | 기준 |
| C++ 잔차 입력 순서 변경 | 8 | 36.72초 | 기존 C++과 비트 일치 |
| 기존 C++ | 4 | 19.73초 | 기준 |
| 참조·텍스트 early block을 2스텝씩 배치 | 4 | 20.84초 | 최대 잠재 차이 2.22, RMSE 0.0817 |
| early block을 스텝마다 미리 계산 | 4 | 19.03초 | Python과 비트 일치 |

512×512 텍스트 전용(출력 1024·텍스트 80 토큰): 기존 C++ 16스텝 36.74초, `mx::compile` 36.94초, 최종 잠재값은 Python 및 C++ 기준과 비트 일치. 한 번씩 측정했으며 이 경우 그래프 컴파일의 이득은 확인되지 않았다.

참조·텍스트 early block은 다른 스텝과 독립적이지만 target timestep에는 의존한다. 두 스텝을 묶으면 MLX가 사용하는 행렬곱 경로와 반올림이 달라져 결과가 달라졌다. 이 한 번의 결과로 시각적 품질 차이나 원인을 확정하지 않는다. 이 실험은 기본 경로에 적용하지 않았다. 잔차 입력 순서 변경은 제한된 사례에서 비트 일치했으나, 부동소수점 예외 값이나 여러 입력의 동등성은 검증하지 않았다.

## 추가 검증과 적용 판단

같은 편집의 16스텝 전체 생성 경로에서 컴파일 75.91초, 직접 실행 74.28초였다. 각각 1회이며 이미지 픽셀은 완전히 같았다. 앞선 직접 실행 실험의 결과와 방향이 달라 일관된 가속으로 볼 수 없어 기본 적용을 철회했다.

33개 블록이 하나의 컴파일된 그래프를 공유하는 실험은 4스텝 19.06초, 잠재값 비트 일치로 뚜렷한 개선이 없어 적용하지 않았다. CPU 분할 20%, 30%, 45%의 4스텝 단일 측정은 각각 20.90초, 18.13초, 18.77초이며 정상 상태 스텝 시간은 30%와 45%가 약 4.44초로 거의 같았다. 이 단일 실험만으로 기본 분할을 바꾸지 않았다.
